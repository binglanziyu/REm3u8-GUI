## 修复清单

### F1【高】Json.cs — 递归深度上限（分析 #1）
- `ParseValue/ParseObject/ParseArray/Write` 增加 `depth` 参数，`MaxDepth = 256` 超限截断（解析返回 Null、序列化写 null）。
- 堵死：恶意/畸形深层嵌套 JSON（入口：update.json、GitHub API）触发不可捕获的 StackOverflowException 直接杀进程。

### F2【高】JobRunner.cs — Pump 线程竞态（分析 #2）
- 启动时先取局部 `TextReader stdOut/stdErr` 再闭包捕获（原实现线程被调度时才解引用 `proc` 字段，与 `Dispose` 的 `proc=null` 竞态）。
- `Pump` 拆出 `PumpCore` 并整体套 try/catch + `Note.Swallow`：泵线程未处理异常在 net48 下会终止整个进程。

### F3【中】Text.cs — MoveAtomic 丢失窗口（分析 #3）
- 原逻辑 `File.Replace` 失败 → `File.Delete(dst)` → `File.Move`，Move 再失败则目标永久丢失。
- 新逻辑：Replace 失败后把旧目标暂存 `dst + ".old"` → 换入 → 成功删旁路、失败还原旁路。配置（Config.cs）与引擎 exe（EngineManager.cs）的覆盖保存不再可能双丢。

### F4【高】MainForm.cs — 拖入文件全量读取（分析 #4）
- `File.ReadAllText` 全量读改为 `ReadHeadText(first, 65536)` 限长读取；拖入文件夹给出提示；修掉 `.json && .resume.json` 死条件（普通 .json 原先掉进全量读取分支）；无链接时给状态反馈。

### F5【高】Http.cs + Prechecker.cs — 直链预检整包进内存（分析 #5）
- `GetText` 增加 `maxChars` 重载（旧签名委托不限量，UpdateChecker 行为不变）；预检只读前 256KB。
- 堵死：粘贴直链 mp4 时预检把整个响应体读成 string（2GB 文件 ≈ 4GB 内存）。

### F6【高】MainForm.Log.cs — 日志渲染卡顿（分析 #6）
- 每拍最多渲染 300 行，余量进 `logBacklog` 下一拍继续（顺序不变、不丢行；`ClearLog` 同步清积压）。
- `TrimLog` 触发阈值从 `max + 20000` 放宽到 `max + max/2`：裁剪是 O(全文) 的 RTF 重排，摊薄频率约 5–10 倍。
- 深层优化（ThinScroll 联动、逐行 AppendText 合并）留给第二批 #30。

### F7【高】EngineManager.cs — tag 路径穿越（分析 #7）
- tag 先过 `Safe.FileName` 再断言 `Path.GetFileName(tagName) == tagName`，不满足回退时间戳。
- 堵死：恶意 update.json/镜像的 `tag_name` 带 `\ / ..` 时安装目录逃出 `EngineDir`，连带 `CleanupOldVersions` 误删。

### F8【高】EngineManager.cs — tar 兜底绕过 Zip Slip + zip bomb（分析 #8、#9）
- zip 解压改为逐条 try/catch：单个坏条目跳过继续，不再把整个 zip 打回 tar 兜底。
- tar 兜底**仅限 gzip 魔数（1f 8b）文件**：Windows 自带 tar 能直接读 zip，对 zip 兜底等于把应用层 Zip Slip 校验整个绕过。
- 解压总量上限 2GB（按声明大小累计），防 zip bomb 写满磁盘。
- ⚠️ 行为说明（唯一微调）：外层分发从「仅 IsZip 走解压」放宽为「IsZip 或 gzip 都走解压」，让注释里声明的「tar.gz 改名包」真正可达；其余内容仍走原直链 PE 分支，落盘后 `IsPE` 复验不变。

### F9【中】Text.cs — Mask.Secret fail-open（分析 #10）
- catch 分支从 `return text`（返回未打码明文）改为 `Note.Swallow` + `return "****"`（fail-closed）。
- 4 个掩码正则补 `matchTimeout(200ms)`：超时走 fail-closed 兜底，而不是永久挂死。
